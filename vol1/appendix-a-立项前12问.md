# 附录 A · 立项前的 12 个自查问题

> 报价之前必须问清楚的 12 个问题。按数据、权限、时间三轴组织。
> 每题给出“什么答案算过关”和“什么答案是红灯”，**当场就能判断**，不必回来再分析。
>
> 这一页可以单独印出来带去会议现场。

## 怎么用

每题问完当场勾一个灯，把关键**原话**记在旁边——记原话，不要记你的理解。
事后翻脸的时候原话才有用。

**判定规则：任一轴出现红灯，一票否决。**

不是说项目不能做，是说在红灯转成黄灯之前，不进入正式报价和排期。
三轴全部黄灯及以上，才可以开始写范围文档。

---

## 数据轴

> 有没有 · 拿不拿得到 · 质量够不够，是三个不同的问题

### 1. 这类数据，“存在”“能导出”“质量够用”分别是什么答案？

最容易被跳过的一问。“数据都在系统里”回答的只是第一层，
**不代表能被导出、能被用于训练或评估**。三层要分开问，分开记。

| | |
|---|---|
| **过关** | 能说出存放系统、导出方式，以及**已经导出过一次给谁用过** |
| **红灯** | “数据肯定有”，但说不出在哪个系统、谁管、导过没有 |

### 2. 需要多少标注量，你们实际能投入多少人天？谁来标？标错了谁负责？

标注只能由懂业务的人做。外包标注队伍需要业务专家先给规范、后做仲裁。
**客户答不上来投入人天，这个项目的交付周期就是不可控的。**

| | |
|---|---|
| **过关** | 能指名道姓说出谁来标、每周能给多少小时、由谁考核 |
| **红灯** | “标注你们来做就行”——业务判断外包出去，口径一定是错的 |

### 3. 历史数据的统计口径变更过几次？变更点分别在什么时候？

口径变更点决定了跨年对比和趋势分析能不能做。
没问这一条，做出来的“同比下降 12%”可能纯粹是口径改了。
**这类错误一旦进了正式报告，杀伤力极大。**

| | |
|---|---|
| **过关** | 能说出具体年份和改了什么，或者明确说“没改过”并且有人敢签字 |
| **红灯** | “应该没改吧”——等于没有答案，需要自己去数据里验 |

### 4. 数据能不能出内网？能不能上云？有没有涉密或个人信息？

这一条直接决定技术架构——本地化、私有云，还是物理隔离。
**架构定错了，返工的是全部，不是一部分。**

| | |
|---|---|
| **过关** | 明确说出部署形态要求，或者指出该问谁、走什么流程定 |
| **红灯** | “先做起来再说，合规后面再看”——后面看一定推翻架构 |

## 权限轴

> 谁批 · 多久批 · 批不下来有没有绕行方案

### 5. 这份数据或系统访问权限，最终由谁签字放行？

这一轴最容易被低估，因为它在第一次会议上从不以“权限问题”的面目出现，
而是以“**我们内部再对一下**”这种说法出现。

要问的是：拍板的人是坐在这间会议室里，还是一个你从没见过的委员会。

| | |
|---|---|
| **过关** | 点名到人，且这个人在场，或者明确承诺何时见 |
| **红灯** | 会议里没有任何一位有实际批准权的人，决策链完全不清楚 |

### 6. 正常流程审批要多久？卡住了有没有绕行方案？

审批时长如果超过项目周期的一半，**项目实际上还没开始就已经迟到了**。

绕行方案的价值在于把“审批批不下来”从一个会导致停摆的风险，
变成一个有预案的已知条件——比如先用脱敏样本跑通流程、先在客户沙箱里验证。

| | |
|---|---|
| **过关** | 有书面时间承诺，或者有可验证的绕行路径（脱敏样本、沙箱） |
| **红灯** | 审批周期长于项目周期一半，且没有任何绕行方案 |

### 7. 涉及多个权属方的数据，你们实际能授权哪几家？其余的推动路径是什么？

跨部门、跨单位的数据往往分属不同权属方，甲方通常只能协调其中一到两家。
**这不是一次协调会能解决的问题，是这类需求最大的隐藏风险。**
答案决定了范围要不要缩到单一来源先做通。

| | |
|---|---|
| **过关** | 至少一个来源有明确书面授权，可以先做通再横向复制 |
| **红灯** | “我们统一协调”，但说不出哪家已经点头、谁去推 |

### 8. 你们方指定的业务专家是谁？投入多少人天？由谁考核？

业务专家必须由客户出，而且要写进范围文档的**依赖条款**。

他们要交付四样东西：判定口径文档、黄金集真值标注、标注分歧仲裁、
漏检与误报的代价权重。**不落到人和人天，到时候一定找不到人。**

| | |
|---|---|
| **过关** | 点名到人、有人天承诺，且这件事进了那个人的考核 |
| **红灯** | “需要什么我们随时配合”——最常见、也最靠不住的一句话 |

## 时间轴

> 客户说出口的截止日期，和真实的截止日期，经常不是一回事

### 9. 这个截止日期背后，有没有一个具体的外部事件？

申报窗口、汛期、供暖季、上级检查、审计节点、合同续签——
**有具体事件锚定的截止日期是真实的**。

说不出事件、只能回答“希望尽快”的，是可以谈判的软约束，不该被当成硬排期依据接受。

| | |
|---|---|
| **过关** | 能说出具体事件和日期，且核实下来与可交付窗口匹配 |
| **红灯** | 纯粹“越快越好”式的焦虑，且拒绝讨论调整 |

### 10. 是否有多家赛马？几家？评判标准由谁定？

赛马会显著改变投入产出比——同样的工作量，中标概率是几分之一。

更关键的是**评判标准由谁定**：如果标准是竞争对手参与制定的，
或者标准本身就偏向某种技术路线，投入前就该知道。

| | |
|---|---|
| **过关** | 明确告知家数与评判维度，或者明确说不赛马 |
| **红灯** | 回避这个问题，或者说“就找你们聊聊”但要求做完整原型 |

### 11. 甲方直签还是集成商分包？回款绑在哪个验收动作上？

分包链条每多一层，需求传递失真和回款周期都会放大。

“回款绑在哪个验收动作上”这一问**要具体到动作**——
绑在“系统上线”和绑在“连续运行三个月无重大故障”，是完全不同的两笔生意。

| | |
|---|---|
| **过关** | 合同关系清晰，验收动作可判定（能用是/否回答） |
| **红灯** | 验收条件写成“客户满意”“运行稳定”这类无法判定的表述 |

### 12. 有没有信创要求？等保定几级？合规三件事问了吗？

国产芯片、操作系统、数据库的适配会显著改变技术选型和工期，
等保级别决定安全建设的投入。

合规还有三问和它同级，正文（第 11 章 §11.1、第 18 章 §18.6）定为立项前红灯项，
这里一起问掉：**要不要办大模型备案？数据出境落在哪一档？客户是不是关基运营者？**
这三项的审批周期以月计，答不上来按红灯处理。

**这几条留到实施阶段才发现，返工的是整个技术栈。** 属于必须在报价前问清楚的硬约束。

| | |
|---|---|
| **过关** | 信创/等保给出明确清单或明确说无此要求，且有文件依据；合规三问各有答案 |
| **红灯** | “应该没有吧”——政企项目里这个答案八成会翻；合规三问任一答不上 |

## 会后当场结论

| 轴 | 取值 | 灯 |
|---|---|---|
| 数据轴 | 取第 1–4 题里最差的一个灯 | 绿 / 黄 / 红 |
| 权限轴 | 取第 5–8 题里最差的一个灯 | 绿 / 黄 / 红 |
| 时间轴 | 取第 9–12 题里最差的一个灯 | 绿 / 黄 / 红 |

**下一步动作（勾一个）：**

- **三轴全绿** —— 可直接进入范围文档撰写与排期。
- **有黄灯、无红灯** —— 可进范围文档，但**每一个黄灯都必须写进假设或依赖条款**，
  并要求客户书面确认。**黄灯没写进条款，等于默认由你承担。**
- **任一轴红灯** —— 不进入报价和排期。先列出“红灯转黄需要什么”，
  约定下次沟通的时间和责任人，再谈范围。

---

## 两句要记住的话

**第一，退出标准必须能用“是 / 否”直接回答。**
“客户签字的范围文档”能回答，“需求明确了”回答不了。

**第二，四类需求要当场拒绝，不要用“记录下来后续评估”搪塞：**
没有数据支撑的、要求 100% 准确率的、范围无边界的、要求绕过合规的。

含糊其辞的记录会在几周后以“我们上次提过的那个”重新出现，
而且因为没被正式拒绝过，客户会理所当然认为它已经在范围内。
