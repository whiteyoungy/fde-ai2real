## 材料

### 一、这条微课要讲的例子

宁可承认“这是构造的教学示范”，也不假装它们是某篇文章里的真实原例。六组示范里只有一组直接改写自一篇经核实的一手学术论文原句，其余五组都标注了各自的依据来源和构造性质。

### 三、这一页在论证什么

**这一页的主张**：这几组是构造的教学示范，为什么要特意说明

**这一页的其他内容**：早期笔记曾引用某网站一篇文章里的“四句反例→正例”作为验收标准示范。；全量引文审计发现，该页面实际内容是 ATM 卡类型鉴权场景和两张未加文字说明的界面截图。它根本不包含“邮箱密码登录”“界面满意度”这类被引用的文字例句。；这四句引文是编造的，已经从笔记中删除。；本节用重新构造、且明确标注性质的示范替代了它们。

## 要求

**时长**：3–4 分钟　**正文字数**：450–650 字

这一条是**中档**：例子有实质内容但不够撑满一节完整微课。脚本走精简结构——场景、判据、一句总结，不铺陈背景。

写作时守住四条：

1. **从例子进，不从定义进。** 开头三十秒之内要出现这个例子的具体场景，
   不要先讲一段概念再举例。学员点开这条微课，是因为它的标题写着一个具体的事。
2. **把判据说清楚。** 微课的落点不是“记住这个故事”，是“下次遇到同类情况，
   用哪一句话做判断”。脚本结尾要能提炼出一句可以直接用的判据。
3. **来源怎么说就怎么说。** 上面“来源”那一栏里如果写了“实测”“官方”“原文”，
   脚本里可以说得肯定；如果写了“归纳”“推导”“教学示例”“未核实”“合成案例”，
   脚本里必须照实说明，不能升级成确定结论。
4. **不要新编案例。** 需要补充例证时，只能用这门课已有的材料
   （六道关卡、12 个 Lab 的实测数字、四个案例章、两个决策复盘）。

## 输出格式

```
【标题】     一句话，不超过 18 字，要具体不要笼统
【一句话结论】 这条微课要让学员带走的那一句判据
【时长】     预估分钟数

【口播脚本】
（分段写，每段前面标一个时间戳，比如 00:00 / 00:40 / 01:30。
  口语，短句，可以直接照着念。不要出现“接下来我们来看”这类过场话。）

【画面】
（逐段给画面说明：这一段屏幕上应该出现什么。
  可以是课件的哪一页、一张什么表、一个什么数字、一段什么对照。
  不需要设计动效，说清楚画面上有什么就行。）

【随堂测题】
（一道单选或判断题，考的是判据不是记忆。给出正确答案和一句为什么。）

【延伸】
（这条微课往下追可以看教材的哪一节，一行。）
```
