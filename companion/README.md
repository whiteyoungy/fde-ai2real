# 配套手册（Living Companion）

> **这不是书的一部分，是书的保鲜层。**
> 上下册正文写不容易变的东西；这里写每半年就会变的东西。
> 两边的分界线只有一条：**一段内容如果三年后还成立，它属于书；
> 如果明年就要重查一遍，它属于这里。**

**这一层不进 PDF。** `build/build.sh` 只收 `vol1/*.md` 与 `vol2/*.md`，
本目录不参与构建——这是有意的：书印出来之后改不了，这里可以随时改。

---

## 为什么要拆出来

写这两册书的过程中反复撞到同一个问题：**同一页纸上混着两种保质期完全不同的东西。**

以下册第 12 章为例。同一节里有两样东西：

- 「同一个模型系列里，不同参数档位可能用完全不同的 License」——这条判断永远成立。
- 「Qwen2.5-3B 用的是 Research License，72B 用的是 Qwen License」——这条随时会变。

把它们印在同一页上，结果是：**第二条过期的那天，第一条跟着一起失去可信度。**
读者查了一下发现表里的数字对不上，就不会再相信这一章的任何判断——
哪怕真正要教的那一条从来没错过。

所以拆开。书里留判断和方法，这里放数字和型号。

## 维护协议

**这一节是这份手册和一个普通「附录」的全部区别。** 没有维护协议的配套手册
会在两年内变成比书更过期的东西——因为读者对书有心理预期，对「在线材料」没有。

### 一、每一页顶部必须有四行

```
版本：       vN
上次复核：   YYYY-MM-DD
下次复核：   YYYY-MM-DD
复核人：     具名，不写部门
```

**「下次复核」过期而没人动，这一页就要在标题下自动挂一条过期警告**，
而不是默默地继续被当成有效信息用。这条规则和上册第 14 章讲的静默失败是同一件事：
**悄无声息地过期，比明确写着「已过期」更危险。**

### 二、每一条数字必须带三样

| | 为什么 |
|---|---|
| **一手 URL** | 复核时能直接打开，不用重新搜 |
| **抓取日期** | 判断这条有多旧 |
| **可信度分档** | 沿用两册正文那套：一手核对 / 多源交叉 / 二手转述 / 抓取失败 |

分档标准见下册附录 D 的 D.0 一节，**这里不另立一套**。

### 三、什么事件触发计划外复核

不必等到「下次复核」那天，以下任一发生就该立刻更新对应页：

- 表里某个模型/产品发布了新的主版本，或被官方标记为停止维护
- 某份 License 或计费条款改版（**这一条最容易漏，因为它不发新闻**）
- 有读者或学员报告「书里/手册里的数字对不上」
- 自己在真实项目里实测出了和表里不同的数字——**这时候要更新的是数字，
  同时要在书里检查一次：那条判断还成立吗**

### 四、改这里的时候，要回头看一眼书

**这是最容易被跳过的一条，也是唯一一条能防止两边说法打架的。**

每次更新完一页，问一句：**这次变化，有没有推翻书里正文的某一句判断？**

- 没有推翻 → 只改这里，书不动。**绝大多数情况是这种。**
- 推翻了 → 在这一页的「与正文的出入」小节里记下来，
  并且下一版书要改。**不要偷偷只改这里**，那会让书和手册各说各话，
  而读者手上通常只有书。

每一页底部都有「与正文的出入」小节，默认写「无」。

## 给读者：怎么用这份手册

**读书的时候不用打开它。** 正文里凡是要用到这里的地方，都写了指针，
而且正文自带一份带日期的缩减快照——**没有网也读得下去**，
只是数字可能旧了。

**真要做选型、报价、写进合同的时候，打开这里。** 然后做一件更重要的事：
**打开这里给的一手 URL，自己核一遍当天的数。**

这不是推卸责任。这两册书教的核心动作之一就是「拿到一个数字，先查它能核到哪一层」
（上册第 13 章 §13.1 那次溯源练习）。**一份配套手册最好的用法，
不是让你省掉核对，是让你知道该核哪几条、去哪儿核。**

本手册目前随仓库分发，路径 `companion/`。

**正式出版时这里要填一个长期可访问的 URL**，并在两册正文的指针处一并替换。
在此之前，正文里的指针一律写作「配套手册 C1」这样的编号形式，
**不写任何具体网址**——写一个将来会失效的链接，比不写更糟。
