### 这张表里最该记住的一条

**Qwen2.5-3B 用的是 Qwen RESEARCH LICENSE AGREEMENT，条款原文写明
"Non-Commercial" shall mean for research or evaluation purposes only——仅限研究与评估，
不可商用。** 这和同系列 72B 档位那个允许商用（超 1 亿月活需申请授权）的 Qwen License，
是两份完全不同的法律文本。**档位相邻不代表授权条款相邻。**

3B 恰恰是最容易被选中做演示、做实验室环境的档位：参数小、单卡消费级显卡就能跑、下载快。
这意味着它也是最容易在没读 License 的情况下被悄悄用进商用 Demo 甚至生产环境的档位。

**这条判断属于书**（下册 §12.1 正文保留），**具体是哪两个档位属于这里**——
下一次改版之后，很可能就不是 3B 和 72B 了，但「同系列不同档位授权不同」这件事还会在。

### 显存数字的口径

表里标 *笔者估算* 的档位，是按参数量 × 精度字节数推算的**权重体积**，
**未计 KV Cache、未计 batch、未计推理框架自身开销**。
实际部署要按压测数据在估算值上留 20%–30% 余量，不能贴着估算值上限配置。

标 *官方来源* 的两条（DeepSeek-R1-Distill 的 NVIDIA System Card、
GLM-4-9B 的 Hugging Face model-sizer）可以直接对照硬件清单，但前者的原页面抓取受限，
数字来自多信源交叉复述，与按参数量估算的量级吻合，**未逐字核对原始页面**。

## C1.2 托管平台：计费与私有化条款

火山方舟（VolcEngine Ark）、阿里云百炼（Model Studio）、腾讯元器/大模型知识引擎是国内三个主流的托管大模型平台。选型逻辑和上一节的开源模型私有化完全不同：这里买的是服务而不是权重。核心问题从“显存够不够”变成“锁定风险有多大、迁移成本有多高”。

> **可信度说明**：先说清楚这一节能给到什么确定性——三个平台的计费细则本书都没能拿到可逐字核对的官方原文。火山方舟与腾讯元器的文档页只取到目录级信息，阿里百炼的计费表述复核时在页面上定位不回原文。
>
> **这意味着下面涉及具体计费规则、私有化条款的表述，凡是没有标注“已核对原文”的，都不能当成可以直接写进客户合同或报价单的确定数字，写作/交付前必须重新打开官方 URL 逐页核对。**

- **火山方舟**：字节跳动旗下平台，聚合多家第三方模型（含 DeepSeek、Moonshot 等）与自研豆包（Doubao）系列。官方文档确认了一条可以直接引用的事实——**兼容 OpenAI SDK**，即接入方式对齐 OpenAI 的 API 形状。这降低了应用层代码在多个平台间切换的改造成本。私有化部署方面，据搜索摘要另有面向敏感行业客户的选项，可将平台整体部署至客户 IDC。**但具体的部署条件、报价、SLA 承诺本次未核实到官方原文，只有摘要级信息，是本节最大的存疑点**。
- **阿里云百炼**：官方帮助中心确认按输入/输出 Token 分别计价、部分模型阶梯计费。部署侧官方原文说明“预置模型”与“调优后的模型”均可“部署获得独立的、资源专享的推理服务”。这一条已核对官方页面原文，可以视为确定信息。至于“Batch 调用按实时推理价格 50% 计费、上下文缓存仅输入 Token 享受折扣”这条更具体的计费细节，复核时未能在当前页面正文里重新定位到对应字样。页面可能已改版，或该说明位于其他子页。**这条数字本次不能确认仍然有效，报价前必须重新在浏览器里打开页面核实**。私有化部署的具体条款本次未检索到。
- **腾讯元器 / 大模型知识引擎**：腾讯云官方定位为“面向企业客户及合作伙伴的，基于大语言模型的知识应用构建平台”。计费支持“预付费资源包、后付费日结两种计费模式”，来源为官方文档目录的转述，未逐句核对正文。私有化部署条款本次未检索到。

**锁定风险的归纳**：三个平台都以“聚合多模型 + OpenAI API 兼容层”作为卖点，表面上降低了应用层代码的锁定风险。但真正决定迁移成本的，通常不在这一层，而在三个更深的地方：

① 是否支持导出微调后的模型权重。三家在本次核实范围内均未确认可导出。

② Prompt/Agent 编排层是否是平台专有 DSL。百炼的应用编排、腾讯元器的智能体配置，一旦深度使用这层能力，迁移成本会显著高于“只调用基础对话 API”。

③ 私有化部署报价相对公有云 API 的价差。这决定了客户后续想“退出公有云、换成私有化或换供应商”时的实际成本曲线。

**这三点建议在真实选型时直接向厂商销售或已落地案例求证，不要仅凭这一节的搜索结论下断言。** 这也是这一节区别于上一节的地方：上一节的 License 条款是可以逐字核对的一手文本，这一节的计费与私有化条款大量停留在“摘要级、未核实”。两者的可信度分层完全不同，不应该用同样笃定的语气呈现。

> **可信度说明**：这是笔者基于上述有限材料的判断，不是某份官方文件的结论，写作或选型报告里引用时要注明这一点。

**一个决定“要不要选托管平台”本身的边界条件：涉密/物理隔离场景从架构原点就排除了这三个平台。**

涉密网络的通行原则是“涉密计算机不得直接或间接接入非涉密计算机信息系统及国际互联网，涉密计算机和非涉密计算机信息系统之间必须实行物理隔离”。

> **可信度说明**：这条表述在多份保密管理规定里反复出现、说法高度一致，但找不到对应的法规条款编号，见上册第 17 章。

这条原则对本节的直接含义是：**任何涉密网络内的部署都不可能联网调用火山方舟、百炼、腾讯元器这类云端 API。** 只能走 23.1、§10.2 讲的本地化模型私有化路径。

换句话说，本节和上一节不是“选一个”的关系，而是由客户网络环境的密级先做一次前置过滤。密级达标的内网场景直接跳过整个平台层。密级不涉密、只是数据不愿出境或出企业的场景，才轮到在“托管平台”与“本地私有化”之间按锁定风险、迁移成本做权衡。

## 这一节为什么整节移到配套手册

下册 §12.3 原来在书里。移出来的理由不是它不重要，是**它的可信度分档和一本书不匹配**。

上面这一节里，几乎每一条计费与私有化条款都带着「未核实原文」「摘要级信息」
「页面可能已改版」这类限定语——而这些限定语**是对的**，不该删（删掉它们
就成了假装确定，那是这两册书从头到尾在反对的事）。

但一本印出来的书没法带着这种状态存在三年：读者两年后翻到这一页，
看到的是一段「当时就没核实、现在更不知道对不对」的内容，而且没有任何机制提醒他。

放在这里就不一样了——**它有复核日期，过期是显式的。**

**书里留下的是这一节唯一不会过期的那部分判断**（下册 §12.3 现在只剩这几句）：
托管平台买的是服务不是权重，选型的核心问题从「显存够不够」变成「锁定风险有多大」；
而真正决定迁移成本的是三件事——能不能导出微调后的权重、编排层是不是平台专有 DSL、
私有化报价相对公有云 API 的价差。**这三条在 2030 年同样成立，哪怕三家平台一家都不剩。**
