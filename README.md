## 还有一层不进 PDF 的：配套手册

```
companion/          # 会过期的那部分：型号、版本号、License、薪酬
```

**书里写不容易变的东西，`companion/` 写每半年就会变的东西。** 分界线只有一条：
一段内容三年后还成立就属于书，明年就要重查一遍就属于那里。

| | 装什么 | 抽自 | 复核周期 |
|---|---|---|---|
| **C1** | 国产开源模型选型全表；三家托管平台的计费与私有化条款 | 下册 §10.1、§10.3 | 每季度 |
| **C2** | 国产芯片 / OS / 数据库的具体型号、适配现状与性能损耗数字 | 下册 §11.2、§11.3 | 每半年 |
| **C3** | 书里断言过的全部工具版本，以及它们今天还成不成立 | 新建台账 | 每季度 |
| **C4** | 各公司官方披露的薪酬区间与国内对标岗位 | 上册 §1.2、别册三 §2.4 | 每年 |

`build.sh` 只收 `vol1/*.md` 与 `vol2/*.md`，**这一层不参与构建**——
书印出来之后改不了，这里可以随时改。维护协议（复核周期、触发计划外更新的事件、
改这里之后要回头看书的哪一条）见 `companion/README.md`。

**正式出版时要给 `companion/` 一个长期可访问的 URL**，并替换两册正文里的指针。
在此之前正文一律写作「配套手册 C1」这样的编号，**不写任何具体网址**——
写一个将来会失效的链接，比不写更糟。

## 关于本书的事实核查

本书源起于一份 AI 生成的调研报告。写作前对全部素材做了**逐条引文审计**：

| | |
|---|---|
| 核对引文 | 530 处 |
| 修正 | 87 处（错误率 16.4%） |
| 降级至存疑 | 10 处 |

审计总账见 `docs/research/CITATION-AUDIT.md`，按危险程度归纳了七类失真。
修正的内容包括：杜撰的法律条文用字、错配的公司名、四个完全虚构的验收标准示例、
两处悬空的论文引用、一个不存在的薪酬分档表。

这类限定语——那是有意的**，不是行文啰嗦。这本书教的就是在客户现场辨别可疑数字，
自己不能双标。

同理，下册正文里 **3 处代码块标注了“未实测代码”**，每一处都写明了缺什么条件。

## 怎么做实验

12 个实验**全部实现并通过验收**，每个都有自己的 `verify.sh`，
全项通过且退出码为 0 才算完成。

```bash
cd labs/lab-01-invoice-pipeline
cat README.md                  # 先读需求、验收标准与可替换组件
python3 fixtures/generate.py   # 生成夹具（夹具是产物，不入库）
bash verify.sh                 # 验收。全过则退出码 0
```

**几条会省你时间的**：

- **夹具要自己生成。** 仓库只带源码、夹具生成器和安装脚本，不带依赖包、模型权重和生成产物。
  生成器都是确定性的（固定随机种子），跑一次得到和作者完全相同的夹具。
- **别把 `verify.sh` 放进管道测退出码。** `verify.sh | tail; echo $?` 拿到的是 `tail` 的退出码。
  正确写法：`bash verify.sh > /tmp/v.log 2>&1; echo $?`
- **部分实验需要虚拟环境**（Lab-03/04/06/08/10）。`verify.sh` 会自动识别同目录下的 `.venv`。
  装 `sentence-transformers` 前先装 CPU 版 torch，否则会拉进整套 CUDA 依赖，白占几个 GB。
- **部分实验需要 Docker**（Lab-04 的 Qdrant、Lab-10 的 Kafka）。`verify.sh` 自己拉起容器并清理。

需要接模型的实验支持双路径：有 key 用真实推理，无 key 降级到本地 CPU 小模型。
无 key 时验收标准放宽为“机制正确”而非“效果达标”，差异写在各实验的 README 里。
**放宽是如实放宽的，不是把夹具改软**——Lab-06 的无 key 档甚至在 README 里明写
“这一档配置不安全，只用于跑通链路，别照搬到生产”。

## 正文与实验的关系

下册正文里的代码块分三类，标注方式不同：

| 标注 | 含义 |
|---|---|
| `✓ 本段取自 Lab-XX，verify.sh N/N 实测通过` | 代码从跑通的实验里回填，可以照抄 |
| 代码首行注释“示意性骨架，未经实测验证” | 讲清思路用的，别直接上生产 |
| `⚠️ 未实测代码` | 全书**仅剩 3 处**，均写明了缺什么条件 |

这个标注体系从写作初期就在，最初有 27 处 `⚠️`。**做实验的过程反复暴露出正文与实现的矛盾**——
比如某段正文规定“高危阻断、中低危降级”，而同章的代码却在做整体阻断。
这类错误光靠通读审不出来，只有真把代码跑起来才会现形。
