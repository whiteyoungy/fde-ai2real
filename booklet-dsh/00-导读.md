# 导读 · 这本别册写给谁，怎么读

DeepSeek 把自己的 agent harness 开源了：仓库 `deepseek-ai/deepseek-harness`，
命令行名字叫 `dsh`，MIT 许可证，TypeScript 写的 [1]。

它的架构只有一句话：**一切皆插件**。模型适配器是插件，工具注册表是插件，
会话日志是插件，连 agent 循环本身也是插件，因此每一部分都可以从配置里换掉 [2]。
官方文档把这句话说得更硬：**不存在需要打补丁的特权内核。**

这本别册要问的不是“它好不好用”，而是一个 FDE 才会问的问题：

> **这套东西能拆到什么程度？拆开之后，哪些零件能交到客户手里？**

## 先说清楚风险：它现在是开发者预览版

仓库首页自己写着：目前处于开发者预览阶段，**未来将出现破坏性变更** [1]。
本册写作时的版本是 `0.1.1-rc.2`。

这句话对读者意味着什么，要说透：

- **可以拿它学 harness 的结构。** 它把 agent 执行层拆得比大多数同类项目都干净，
  拆法本身是可迁移的知识，跟版本无关。
- **可以拿它做内部工具和验证性项目。** 破坏性变更会让你返工，不会让你赔钱。
- **要签合同的正式交付，先算清返工成本。** 别把一个明说自己会破坏兼容的组件，
  写进一份三年运维期的合同里，除非你已经和客户约定好版本锁定和升级窗口。
  第 7 章会给一份判断清单。

所以本册采用一个和平时不同的可信度做法：

> **可信度说明**：本册所有关于 `dsh` 行为的陈述，都取自仓库的 `b150a551` 提交
> （2026-08-21，`v0.1.1-rc.2`）及其自带的中文文档。
> **这是一个会变的目标，所以每条结论都钉在这个提交上。**
> 你验证时请先 `git checkout b150a551`，行为对不上再看是不是版本已经走远了。
> 本册未对该版本做全功能实测，未实测的地方逐条标了出来。

## 和另一本别册什么关系

本书有两本别册，讲的是同一层东西——**模型外面那层壳**，
沙箱、审批、留痕、边界——但看的角度不同。

| | **别册一 · Codex** | **别册二 · DeepSeek Harness（本册）** |
|---|---|---|
| 主要问题 | 甲方安全部门问“它会不会乱来”，怎么答 | 这套壳能拆到什么程度，拆开怎么交出去 |
| 对象形态 | 一个配置齐全的成品 | 一棵可以逐个换零件的插件树 |
| 许可证 | Apache-2.0 | MIT |
| 在中国现场最大的坑 | 协议只支持 Responses，**多半接不上国产模型** | 是开发者预览版，**会有破坏性变更** |
| 成熟度 | 高，但边界由它定 | 低，但边界由你定 |

**两本不冲突，甚至互补。** 别册一第 5 章那个最大的坑——国产模型的
“OpenAI 兼容端点”绝大多数是 Chat Completions，而 Codex 已经移除了这条协议路径——
在这里有现成的解法，而且是官方文档里逐个开关写明的。**本册第 2 章专讲这件事。**

顺序建议：**先读别册一，再读本册。** 别册一把问题问清楚了，本册给的是另一套答案。
只读本册也行，不需要前置。

## 这两本别册都不进上下册的目录

上册十四章、下册十六章，是一条完整的主线，两本别册都不在这条线上。
它们是**实践册**：上下册讲“该做成什么样”，别册讲“拿一个具体的东西怎么做到那样”。

判断依据很实际——**上下册五年后大致还成立，别册两年就得重写。**
方法论和工具的保质期不一样，混在一本书里，短的那个会拖长的那个。

所以：上下册不依赖任何一本别册；别册单向引用上下册；两本别册之间也不互相依赖。

## 门槛在哪

**你需要的基础**：会用命令行，写过代码，看得懂 YAML 和 JSON。
**不需要**懂 TypeScript、不需要懂 Cordis、不需要当过运维。

第 1 章会讲 Cordis（`dsh` 底下那个插件框架）的概念，但**只讲到你能看懂配置为止**，
不讲怎么写插件——那是它自己的教程该干的事，链接在附录 B。

## 三条读法

别册一按“合规压力”分档。本册的分法不一样，按**你打算把它当什么用**：

### 一、当工具用

**谁**：想找个能接自家模型的 agent 工具，先跑起来看看。
**读**：第 1 章 1.1 节 → 第 2 章（全章）→ 第 3 章 3.1、3.2 节 → 附录 A 的“先跑起来”。
**跳过**：第 5、6 章。
**需要什么**：一台能装 Node 的机器，一个模型端点。

第 2 章是这条路的核心，因为**在中国现场，接不上模型的 harness 等于零**。

### 二、当组件改

**谁**：要在自己的产品里嵌一个 agent，想少写一半代码。
**读**：一档全部 + 第 1 章全章 + 第 4 章 + 第 6 章 6.1、6.3 节。
**需要什么**：会写点 TypeScript 或 Python，知道进程和权限是怎么回事。

### 三、当交付物给出去

**谁**：FDE、交付工程师，要把东西留在客户现场，还要留得住。
**读**：全册，一章不落，重点在第 5、6、7 章。
**需要什么**：进得了客户环境，谈得了合同里的版本条款。

> **一句话判断你在哪一档**：
> **这套东西，最后归谁维护？**
> 你自己 → 一档。你的产品团队 → 二档。**客户的运维 → 三档。**

## 每章讲什么

| 章 | 讲什么 | 档 |
|---|---|---|
| 1 | 一棵可以拆开的树：插件、seam、profile 与 patch | 一·二 |
| 2 | 接得上，才谈得上别的：国产模型、网关兼容、凭据 | **全部，最实用** |
| 3 | 护栏会自报强制力：沙箱、审批、fail-closed | 一·二·三 |
| 4 | 模型可见即已记录：日志、审计事件、遥测边界 | 二·三 |
| 5 | 从会话日志里长出验收集 | **三档，本册原创的一章** |
| 6 | 把它交出去：patch、无头模式、SDK、钩子兼容 | 二·三 |
| 7 | 什么时候不该用它 | 全部 |
| 附 A | 落地清单，按三档拆开 | 全部 |
| 附 B | 参考来源 | 复核时翻 |

**第 5 章是本册唯一一章没有对应官方文档的内容。** 它讲的是把会话日志变成
下册第 9 章那套验收集的原料——**这是本书的推论，不是 DeepSeek 的主张**，
章内会再标一次。要是你只想知道这东西怎么配，跳过它没有损失；
要是你在意“项目结束之后客户手上剩下什么”，那一章是全册最该读的。

## 这本别册不打算做什么

- **不做安装教程。** 官方 README 三行命令写完了，抄在附录 A 第一段。
- **不评测它写代码写得好不好。** 那个结论三个月过期一次，而且它现在是预览版，
  拿预览版做能力评测对谁都不公平。
- **不劝你换掉 Codex。** 第 7 章会明说哪种情况下应该继续用别册一那套。
- **不当它的推广材料。** 本册指出的限制比优点多，这是故意的——
  优点在它自己的文档里写得很清楚，限制没有。

## 挂在四层骨架上

上册第 2 章立了本书的四层骨架：**公理**（风险转移）、**过程**（六道关卡）、
**结果**（证据、控制、接管）、**资产**（验收集）。本册每一章都挂在后两层上：

| 层 | 本册哪一章 | 这个 harness 提供什么 | **你据此能当场问出口的那句话** |
|---|---|---|---|
| **证据** | 第 4 章 | 只追加的会话日志、成对的审批审计事件、可查询的语料 | 出了事，查得到是哪一次、谁批的吗 |
| **控制** | 第 3 章 | 沙箱模式、审批策略、权限预设，而且失败时一律拒绝 | 越权那一下，它是拦住还是记一笔 |
| **接管** | 第 6 章 | 配置补丁、无头运行、SDK 嵌入、既有钩子兼容 | 我们走之后，他们改得动吗 |
| **资产** | 第 5 章 | 日志作为回归集的原料（本书推论） | 这些日志，能直接变成验收集吗 |

第 1 章和第 2 章是前置——**接不上模型、拆不开结构，后面三层一层都立不起来。**
这两章对应的问句是：**我只换其中一块，动得了吗？** 和 **换成国产模型，改几行？**

**最后那一列才是这本别册真正想留给你的东西。** 中间那列是这个 harness
今天的样子，它会变，甚至这个项目本身都可能停更；而最后一列换一个项目照样能问。
**读完这本别册，如果只记住一样，记这五句问话，别记那些机制名词。**

## 读完你能做什么

**一档读完**：

1. 把 `dsh` 接到一个国产模型网关上，包括那两个最常见的拒绝原因怎么改。
2. 说清楚这套东西的密钥存在哪、什么时候会被读、页面上能不能看到明文。
3. 判断当前这台机器上沙箱是完全生效还是部分生效——**并且知道为什么这个区别要紧。**

**二档再加**：

4. 用一份 patch 文件改掉启动树里的任何一条，而不去改它的源码。
5. 说清楚哪些事件进日志、哪些事件进模型上下文，两者为什么不是一回事。

**三档再加**：

6. 把 harness 的配置本身做成可交付、可评审、可回滚的一份东西。
7. 从会话日志里捞出第一条回归用例。
8. 拿着第 7 章那张表，判断你手上这个项目现在到底该不该用它。

**如果你只有十分钟**：翻到第 2 章 2.2 节，看那两个开关。
那是本册单位篇幅价值最高的一段。

## 这本书是怎么写的：AI 辅助的部分

**署名只写人。** 写作过程中大量用了 AI 工具（Claude、Gemini、Codex），
它们参与初稿、结构重排、检索线索、代码与图表生成，以及章节编号、交叉引用、
术语统一这类机械核对。

**三样没有交给它们**：选题与判断（哪条判据成立、什么算本书原创、哪个数字不采信）；
出处的核对状态（逐字核对过的、只核了摘要的、二手转述的分开标，不合并）；
以及实测（标“已实测”的是在真机上跑过的，不是模型说它能跑）。

完整说明见上册导读同名小节，其中记着写作过程中真实发生过的一次
“案例整个是搜索摘要凭空生成的”事故——书里那些限定语就是从那次开始加的。
