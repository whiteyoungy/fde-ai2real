## 三、下午研讨任务书 · 两个决策复盘

### 分组

每组 4–6 人。奇数组读**复盘一**（物理隔离环境下的主权 AI 部署，上册第 19 章），
偶数组读**复盘二**（混乱数据与自主对账，上册第 20 章）。

### 45 分钟怎么用

| 时间 | 动作 | 产出 |
|---|---|---|
| 0–10 分钟 | 读完 §1–§3（背景、真实冲突、被否决的方案） | 无 |
| 10–25 分钟 | 组内讨论：这些方案为什么被否决？判据是什么？ | 一句话写下每个否决的判据 |
| 25–35 分钟 | 两组交换，对着 §4（最终架构决策）核对 | 找出自己漏掉的那条约束 |
| 35–45 分钟 | 全场讨论：哪些经验可迁移，哪些不可直接迁移 | 各组给一条可迁移经验 |

### 研讨题

**复盘一**：客户 IT 部门最初设想的“折中方案”是用加密专线把隔离网络和云端大模型 API
连起来。它在第一次合规评审就被否决——理由不是延迟或带宽。**换成你，
你会用哪一句话否决它？**

**复盘二**：被否决的方案二（传统告警值班）“不是方向错了，是在这个事件量级下
工程上撑不住”。这句话意味着它在某个量级下是对的。**那个量级的分界线在哪？
换成你的项目，你会怎么算这笔账？**

### 4.2 撤不回来的后果清单（定灰度比例之前先填）

```
这次放量期间如果它错了，哪些后果撤不回来？

□ 模型版本 / 提示词 / 配置        → 能撤，切回上一版，分钟级
□ 已经写回业务系统的数据          → 难撤，补偿动作是：____________
□ 人已经照着建议做了的事          → 撤不回来，具体是：____________

结论：
□ 有撤不回来的后果 → 第一档灰度比例定为 ____%，观察窗口 ____ 天
□ 全都撤不回来     → 不从灰度开始，先加一道人工复核
```

### 5.2 48 小时原型完整节奏（M10 只放了前六段）

| 时间段 | 目标 | 技术债处理 |
|---|---|---|
| 0—2h | 确认数据与系统访问权限 | 不涉及 |
| 2—6h | 按四步法搭骨架 | 记一行“骨架用假数据”，触发条件写“接入真实数据前必须换掉” |
| 6—10h | 最窄那条业务路径换成真实数据 | 无 |
| 10—14h | 实现核心业务规则 | 登记“规则硬编码”，象限标“审慎-刻意” |
| 14—18h | 接到一个能给人看的输出 | 无 |
| 18—24h | 拿着原型回访客户 | 无 |
| 24—30h | 把最不确定环节替换为真实实现 | 更新登记表 |
| 30—36h | 补齐最低限度错误处理（只覆盖会导致演示中断的路径） | 无 |
| 36—42h | 演练一次完整演示，走一遍兜底预案 | 无 |
| 42—48h | 清理不留下来的原型代码 | 集中复核登记表，标出退出评审前必须还的 |

### 5.3 技术债登记表字段

| 字段 | 说明 |
|---|---|
| 问题描述 | 具体欠了什么债，一句话说清楚 |
| 所属象限 | 审慎-刻意 / 鲁莽-刻意 / 鲁莽-无意 / 审慎-无意，四选一 |
| 预估偿还成本 | 工时或故事点 |
| 触发条件 | 这块代码所在功能被再次修改时优先还 |
| 状态 | 待还 / 已还 |

**登记时机**：每走一步捷径当场记一行，不留到复盘会才回忆。
**偿还时机**：绑定在“下一次要动这块代码”的时刻，不是留到最后开一个还债迭代。

### 5.4 交接包条目（M12 只讲了硬判据）

系统文档（架构图、数据流图、部署步骤、回滚方案）；明确书面的服务等级约定；
值班手册（针对上一季度最常见的**五类**故障，每类单独写一份含具体命令、
具体看板链接、具体升级联系人的手册，而不是一份笼统的“故障处理指南”）；
交接纪要发到团队可见的共享频道，不能只是口头或私聊交接。
