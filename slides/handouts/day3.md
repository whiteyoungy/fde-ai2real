| # | 任务 | 验收判据 |

| ③ | 换三种分词方式各跑一遍 BM25 | 复现课上那张 10 / 47 / 57 / 54 的表 |
| ④ | 拿一条错误回答，用三分法脚本定位根因 | 说出是检索失败、数据污染还是模型幻觉 |

**参考结果**：混合检索 58/59，纯向量 53/59。语料 1241 篇中文企业文档、59 条查询。

**跑不出书上那两个数字不是失败——能说清为什么不一样才是通过。**

### 第 ③ 项的对照表（跑完自己填）

| 分词方式 | 总分 | 语义改写类 | 埋编号类 | 你跑出来的 |
|---|---|---|---|---|
| 不分词（按空格切） | 10/59 | 0/8 | 0/40 | |
| 单字 unigram | 47/59 | 7/8 | 29/40 | |
| 字符 bigram | **57/59** | 6/8 | 40/40 | |
| jieba 分词 | 54/59 | 3/8 | 40/40 | |

**要看出的**：同一个“更先进”的方案，在不同查询类型上方向相反。
jieba 把“核销”“时限”切成完整词之后，用户问的“多久”“到账”一个都对不上；
bigram 切出的碎片反而有更多机会撞上。

### 第 ④ 项：三分法脚本三个函数

| 函数 | 判断什么 | 输出 |
|---|---|---|
| 第一步 | 底层精确查找，绕过检索链路直接看知识库里有没有 | 没有 → 内容缺失，补内容，不用往下走 |
| 第二步 | 看这次检索实际返回的上下文里有没有包含它 | 没命中 → 检索失败；命中但内容错 → 数据污染 |
| 第三步 | 把回答拆成若干条陈述，逐条检查能否从上下文推出 | 有陈述找不到支持 → 那一条就是幻觉的具体位置 |

**顺序不能跳。** 直接从第三步开始查，会把“知识库里压根没有”误判成“模型幻觉”。

## 四、可直接带去现场的清单

### 4.1 代码交付自检（四条硬线）

```
□ 路径、阈值、配置都是参数注入的吗？还是有一条写死在代码里？
□ 严格模式的类型检查跑得过吗？签名里还有裸露的 Any 吗？
□ 日志能按字段检索吗？还是把变量拼进了一句人话里？
□ 每个 except 分支要么记日志、要么重新抛出了吗？有没有空 pass？
□ 单测能不能在不连任何外部资源的前提下跑通核心分支？
□ 依赖锁到整棵树了吗？目标平台的 wheelhouse 打过一次吗？
□ 底座和现场层是两个仓库、两份构建产物吗？底座版本戳早于合同签署日吗？
```

### 4.2 现场第一天的五个 SQL 模板

| 模板 | 查什么 | 常见的坏结果指向 |
|---|---|---|
| 空值率 | 对每个关键字段各算一次 | 口头描述和实际分布对不上 |
| 重复率 | 先看总体，再钻到具体重复的主键上 | 主键不唯一 |
| 分布偏移 | 按天摊平某个分类字段占比，跟历史基线比 | 上游系统变更或字段口径漂移 |
| 外键孤儿 | 子表里存在、父表里查不到的记录 | 数据同步或分批迁移遗留 |
| 时间戳异常 | 更新早于创建 / 晚于当前 / 早于 1990 年 | ETL 乱序、时区没转、哨兵默认值 |

**SQL 只负责把事实摆出来，不负责替你下结论。** 一个可选字段空值率 60% 很正常，
一个主键字段空值率 0.1% 就该警惕——判断标准要靠跟业务方对话确认。

### 4.3 “连不上”四层排查

```
① DNS   → 解析到的是哪个地址？内网可能做了分离视界解析
② TCP   → 端口通不通？白名单申请周期以周计，方案定稿当天就要提
③ TLS   → 证书链完整吗？内网自签 CA 的根证书导入每个消费方了吗？
④ 应用层认证 → 凭据对不对？这一层必须建立在前三层都排除的前提下
```

**很多人一上来就怀疑认证配置，因为认证报错信息最显眼。**
走 VPN 分离隧道导致的 DNS 问题，报错通常是“连接超时”而不是“域名解析失败”。

### 4.4 客户话术翻译表（每听到一句，追问一层：谁批、多久、批不下来谁受影响）

| 你听到的 | 通常的实际含义 |
|---|---|
| “网络是通的” | 办公网到那台服务器是通的。你的容器在另一个网段，未必 |
| “你申请一下就行” | 有一张要走审批的工单，周期以周计 |
| “这个我们有接口” | 存在一份接口文档。不保证那个接口现在还在跑 |
| “等下个变更窗口” | 生产变更集中在固定时段，错过要等下一轮 |
| “安全那边过一下” | 一次独立评审，可能要你交镜像清单、扫描报告、代码扫描结果 |
| “数据可以给你” | 可以给你看。未必可以拷出来，更未必可以进你的训练流程 |

### 4.5 接一份新语料之前

```
□ 数据契约写成能跑的断言了吗？三层都有吗——结构、语义、时效？
□ 三种漂移分别怎么处理定了吗？（只有破坏性漂移是硬阻断）
□ 脏数据的四条路径判据写下来了吗？还是只有丢弃和硬塞两个极端？
□ 文档属于哪一类解析难点？诊断过了吗，还是直接开始比工具跑分？
□ 分块策略是按文档类型选的吗？
□ embedding 选型四个维度都过了吗？换模型的一次性重算成本估进去了吗？
□ 三分法诊断脚本接进管道了吗？
```

## 五、课上没展开的完整材料

### 5.1 韧性四件套的完整配置清单

| 件 | 要定的参数 | 一起定，不能分开拍 |
|---|---|---|
| 幂等 | 键的生成方、覆盖范围、有效期 | 有效期要长于调用方可能重试的最长窗口 |
| 退避 | 基准间隔、倍数、上限、抖动策略 | 上限决定了幂等键的有效期下界 |
| 超时预算 | 端到端总预算、每一跳的分配 | 下游重试次数受剩余预算约束，不是固定 N 次 |
| 熔断 | 失败率阈值、冷却时间、半开试探量 | 降级走哪条路是业务判断，要写进范围文档 |

### 5.2 OAuth2 四种可用授权方式

| Grant | 适用场景 | 关键约束 |
|---|---|---|
| Authorization Code ＋ PKCE | 有用户参与、需要授权同意 | OAuth 2.1 要求所有客户端类型都必须用 PKCE |
| Client Credentials | 机器对机器，无终端用户 | 只涉及两方，不涉及资源所有者 |
| Device Authorization | 无浏览器或输入受限的设备 | 用户在另一台设备上完成授权，客户端轮询换令牌 |
| Refresh Token | 长期令牌换短期访问令牌 | 应启用轮换；检测到作废令牌被复用应撤销整个令牌家族 |

**已被移出 OAuth 2.1 的两种**：Implicit grant、用户名+密码直接换令牌（ROPC）。
客户老系统要求用后者对接时，主动指出这是遗留设计，不要照单全收。

### 5.3 三种能力按症状选，工具按能力选

| 症状 | 缺的是 | 上什么 |
|---|---|---|
| 需求说不清，做出来不是想要的 | 规格 | Spec Kit（或任一规格工具） |
| 规格写了，但和代码对不上，没人敢信 | 变更轨迹 | OpenSpec |
| 小改动也要写一堆文档，团队开始抵触 | 分档规矩 | 先定分档表，工具不用换 |
| AI 干活没规矩，随手就改、说做完了拿不出证据 | 工程纪律 | Superpowers |

### 5.4 OpenSpec 增量操作四种

| 操作 | 含义 | 约束 |
|---|---|---|
| ADDED Requirements | 新增的行为 | — |
| MODIFIED Requirements | 改掉的行为 | **必须写出改完后的完整内容**，不是只写差异 |
| REMOVED Requirements | 废弃的行为 | 必须写 Reason 与 Migration |
| RENAMED Requirements | 只改名字 | 用 FROM:/TO: 格式 |

**两个坑**：场景必须**正好四个井号**（三个井号或列表项不报错、静默失败）；
默认上报匿名使用统计，**进客户内网之前先关掉，并写进软件物料清单**。
