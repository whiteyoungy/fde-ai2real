## 二、上机任务书 · Lab-11 工作流发现

材料包：`labs/lab-11-workflow-discovery/`（纯文档演练，不需要写代码）

### 场景

一家中型制造企业客户，要求给“设备故障报修流程”引入 AI 辅助分诊。

材料包内含：三份不同角色的访谈记录草稿（车间班长、维修工程师、设备科科长）、
一份现有报修系统的字段清单、一份三年前制定且未更新过的“标准报修流程”文档、
五封干系人往来邮件（其中至少一处管理层描述与访谈记录矛盾）。

### 分组

每组 4–6 人，高管与工程师混编，**每组至少一名高管**。

### 四项产出（70 分钟）

| # | 产出 | 判据 |
|---|---|---|
| ① | 标注访谈记录：哪些是待验证假设，哪些是当场确认过的事实 | 两类都有，且能说出区分依据 |
| ② | 判断这个流程适合用服务蓝图还是本体拆解，写清判断依据 | 依据写出来了，不是只写结论 |
| ③ | 从材料包里找出至少一处需求错位的证据 | 写清是七种里的哪一种、识别依据是什么 |
| ④ | 一份范围文档草稿 | 覆盖问题陈述、范围内／范围外初稿、待确认假设清单 |

### 最后 20 分钟：交换检查

两组交换第 ④ 项产出，各自找出对方那份范围文档里**最先会在第 4 关爆炸的一条**。
按这个顺序问：

1. 有几条量化验收指标？超过 3 条的，多出来的那几条在验收时会互相打架。
2. 假设条款有没有一个“客户方确认”的动作附着在上面？
3. 依赖条款里有没有出现“客户配合”“由各方协商”这类不点名的写法？
4. 有没有哪一条验收标准，两个人念完会给出相反的判断？

找不出来，说明上午那张四栏表还没真正听懂——第 2 关的通过标准写的就是这四件事。

## 四、课上没展开的完整材料

课件里点到但没占篇幅的东西，完整版放在这里。

### 4.1 职责边界防守五句话术（课件 M3 只讲了结构和两句）

**1. 直接划界**——客户提出明显超范围要求，需要第一时间划清界限：

> 很抱歉，这项功能／组件／服务不在本项目范围内。要不要约个时间讨论一下扩大项目范围和预算，
> 来容纳这个新需求？

**2. 转化为报价讨论**——不生硬拒绝，把“要不要做”转化为“愿意为此多付多少钱”：

> 我们目前的协议是【当前条款】，费用是【约定金额】。根据你说的，你想加上【新需求】……
> 我愿意以【新费用】来做这件事。

**3. 拉回书面依据**——客户忘了当初签的范围：

> 很遗憾，你提的这个要求超出了我们最初的项目需求范围，为方便起见我把原始文档
> 附在这封邮件里……

**4. 升级决策**——量级较大的变更，不自己当场拍板（无论答应还是拒绝）：

> 谢谢分享这个好想法，我理解你为什么想把它加进项目。不过这个量级的事需要
> 我们的项目发起人批准。

**5. 内部管理**——这是说给团队听的，不是对客户说的：

> 请不要过度地“义务加戏”。保持在最初项目需求范围内很重要……

**向上沟通句式**（对内，给你的经理）：

> 这周有 N 场演示／客服支持请求没有经过资格评估，如果继续这样，X 客户的交付时间
> 会往后推 Y 天——我们要不要先约定一个前置门槛？

### 4.2 换用理由访谈脚本（课件 M4 只在工具表里列了一行）

按时间线顺序提问：

- “你最早是怎么开始需要解决这个问题的”
- “你希望达到的最终结果是什么”
- “在找到现在这个办法之前，你手动做过哪些尝试”
- “你是什么时候开始觉得也许该换个办法解决这件事的”
- “用现在这个办法之前，你原本希望它能解决什么”
- “它有没有真的解决你希望它解决的问题”
- “你当时有没有什么顾虑或者不确定的地方”
- “你有没有找别人商量过或者查过其他资料”
- 收尾问“还有什么你觉得我该知道的”

**配套的四力框架**——把“决定换掉某样东西”拆成四种力量，访谈时明确区分对方说的
每句话对应哪一种：

| 力量 | 原文那个换床垫的例子 |
|---|---|
| 推力 | 一整年没睡好 |
| 拉力 | 一款完全不同的记忆棉床垫 |
| 焦虑 | 没试过就买，万一不合适呢 |
| 惯性 | 那张两千美元的旧床垫，舍不得扔 |

一条提醒：“你觉得你以后会怎么做”这类问题拿到的是**理论化的说辞，不是真实行为回忆**。
要聚焦“你当时具体做了什么”。

### 4.3 变更单 20 个字段（课件 M5 只讲了最容易被删掉的两栏）

项目名称 / 变更请求编号 / 提出人 / 提交日期 / 联系方式 / 优先级 /
对交付物的影响 / **不响应变更的影响** / 需要完成的日期 / 审批人 /
受影响的任务范围 / 成本评估 / 质量评估 / 预计耗时 / 额外投入 /
对截止日期的影响 / **备选方案与建议** / 备注 /
签署结果（接受 / 拒绝 / 延后 / 需要更多信息，四选一）/ 签字栏

加粗的两栏最容易被简化掉。省略它们，变更单会退化成一张“客户要什么就报什么价”的
接单表，起不到任何过滤作用。
