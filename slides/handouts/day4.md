## 二、上机任务书 · Lab-05

环境：`labs/lab-05-evals/`，有 key 与无 key 双路径均已验证。

| # | 任务 | 验收判据 |
|---|---|---|
| ① | 跑通三层评估集，看基线分数 | 三层各出一个分数，门禁放行 |
| ② | 注入劣化改动 | 护栏被关闭 ＋ 检索结果被注入噪声 ＋ 一个历史故障被重新引入 |
| ③ | 重跑门禁 | **必须阻断**，且能说清是四条阻断条件里的哪几条触发的 |
| ④ | 恢复改动，重跑门禁 | **必须放行** |

**第 ③ 项的“能说清是哪几条触发的”才是真正的验收点。** 门禁红了不算通过——
红了并且你能指着日志说出“回归集第 N 条复发，零容忍，硬阻断”才算。

### 三个注入各自该触发哪条阻断（跑完自己对）

| 注入的改动 | 该触发哪条 | 实际触发了哪条 |
|---|---|---|
| 护栏被关闭 | 对抗集通过率 | |
| 检索结果被注入噪声 | 检索指标相对回退 ＋ 黄金集综合分 | |
| 一个历史故障被重新引入 | 回归集通过率（零容忍） | |

**如果三个注入只触发了一条阻断**，说明另外两条的阈值定得太松，或者压根没接上。

### 分开注入，不要三处一起注

三处一起注入、门禁一次全红，你学到的只是“门禁能红”。
分开注入，你才能看出四条阻断条件各自守的是什么。

## 三、回去怎么落：门禁接入顺序

从判据最清楚的往判据最模糊的走。

```
① 回归集那一条
   零容忍、判据最清楚、最不需要标定阈值。
   而且它一定能立刻发挥作用——你手上一定有过历史故障。

② 检索指标相对回退
   用相对值而不是绝对阈值，绕开了“阈值定多少”这个难题。

③ 黄金集综合分
   要先有黄金集，而黄金集要业务专家标注。
   排第三不是因为不重要。

④ 对抗集分级
   需要对抗集先按风险场景分好类。
```

**反过来先接黄金集，会卡在“阈值定多少”上，然后整件事就搁置了——
这是门禁最常见的死法。**

## 四、可直接带去现场的清单

### 4.1 交付一个 Agent 之前

```
□ 系统提示词分层了吗？改一条业务规则要动几层？
□ 上下文预算分配表画了吗？输出预留了吗？
□ RAG 四件套里每上一件，都回答过“什么情况下不值得上”吗？
□ RRF 的 k 值是这个后端自己的默认值，还是从别家抄来的？
□ 工具描述里，不可逆工具的“不适用”那一段比“适用”那一段长吗？
□ 危险工具的误触发做成可重复跑的检查了吗？
□ 循环拓扑配迭代上限了吗？上限触发时的动作定义了吗？
□ 人在回路用的是动态中断吗？检查点配了吗？节点副作用幂等吗？
```

### 4.2 交付一套部署包之前

```
□ 多阶段构建了吗？运行时镜像里还有编译工具链吗？
□ 容器以非 root 运行吗？基础镜像锁到具体 tag 了吗？
□ 推理服务配了宽松超时的启动探针吗？
□ 离线包五步齐了吗？验签能不能在断网环境完成——不只是签能不能？
□ 语义缓存的阈值是在自己的数据上标定的吗？先确认过两组分布分得开吗？
□ 埋点装饰器的自动捕获关掉了吗？异常信息里的原文过脱敏了吗？
□ 成本看板有没有把缓存节省单独算一条线？
□ 生成内容的显式和隐式标识都做了吗？
```

### 4.3 搭一套评估之前

```
□ 三层评估集分别有多少条？黄金集是按难度／意图／领域分层采样的吗？
□ 检索指标和生成指标分开测了吗？
□ 评估用的 k 值和生产管线实际塞进提示词的块数对齐了吗？
□ 裁判模型选的是哪一家？跑过正反两个顺序吗？加过锚定示例吗？
□ 裁判本身锁版本了吗？有没有一组固定样本定期回归裁判？
□ 分数掉了的时候，先分清是协变量、先验还是概念偏移了吗？
□ CI 门禁四条阻断条件都接上了吗？回归集那条是零容忍吗？
□ 评估管道自己有人监控吗？它挂了谁会知道？
```

### 4.4 国产化选型五步

```
① 商用授权能不能接受    → 一票否决，不进入后续任何一步比较
② 显存预算能不能满足    → 估算值要留 20%–30% 余量，不能贴着上限配
③ 上下文长度是否够用    → 配置默认值和官方声明的最大值经常不是一回事
④ 是否需要函数调用      → 都支持某种形式，但成熟度不一样
⑤ 中文能力是否达标      → 没有权威打分表，只能拿客户真实语料实测
```

## 五、三张对照表（现场速查）

### 5.1 Agent 四类故障

| 故障 | 怎么防 |
|---|---|
| 工具调用失败 | 区分三种：瞬时失败按退避重试；参数错误重新生成或转人工；工具不可用则降级 |
| 幻觉工具调用 | 调用前校验工具名在注册表内，不在就直接拒绝 |
| 死循环 | 循环拓扑必须配迭代上限，上限触发时的动作要明确定义 |
| 状态污染 | 用结构化记忆而不是流水账，关键字段可被覆盖、可被校验 |

### 5.2 三类漂移

| 类型 | 变的是什么 | 处置方向 |
|---|---|---|
| 协变量偏移 | 输入分布变了，映射没变 | 输入端补数据、扩检索覆盖面 |
| 先验偏移 | 答案分布变了，问题本身没变 | 重新标定阈值与类别权重，**别急着改模型** |
| 概念偏移 | 映射本身变了 | **必须重做标注。补数据没用，因为旧标注现在是错的** |

### 5.3 CI 门禁四条阻断条件

| 检查项 | 阻断条件 |
|---|---|
| 黄金集综合分 | 低于设定阈值阻断 |
| 回归集通过率 | **任何一条历史故障复发，硬性阻断，零容忍** |
| 对抗集通过率 | 低于阈值时按风险等级分级：高危阻断，中低危降级为告警 |
| 检索指标相对回退 | 相对上一版本下降超过设定百分比，阻断 |
