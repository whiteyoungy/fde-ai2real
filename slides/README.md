# FDE 课件：五天实战课程 ＋ 一份宣讲版

基于《前线部署工程师（FDE）：把 AI 交付到真实世界》（上下册 ＋ 两本别册 ＋ 12 个 Lab）改编。
设计文档：`docs/superpowers/specs/2026-08-26-五天课程与课件设计.md`

## 怎么生成

```bash
python3 slides/artifacts.py               # 示例产物图（assets-slides/*.png），课件依赖它
python3 slides/build_slides.py            # 全部（五天课件 ＋ 宣讲版）
python3 slides/build_slides.py day1 day3  # 指定某几天
python3 slides/build_slides.py quotes     # 只出宣讲版《FDE 十二条》
python3 slides/build_slides.py exec       # 只出高管简报（给决策者的 FDE 方法论，60–90 分钟）
python3 slides/check_layout.py            # 只跑版式核算
```

产物是同目录下的 `.pptx`，按仓库现有的 `*.pptx` 规则不入库，需要时现生成。

**本机禁用了 LibreOffice**（曾导致系统假死），所以不要转 PDF 预览。版式问题靠
`check_layout.py` 按坐标核算：它把每个文本框的渲染高度估出来，检查溢出页底、
文字撑破卡片、压到下方元素、单页过密四类问题。生成脚本会自动跑它。

另有独立单场：**高管简报**（`exec.py`，30 页，60–90 分钟）——给甲方高管/决策者的方法论专场：时代命题、数字口径、计价=责任分配、六关+验证门禁+叫停判据表、六问供应商。不讲代码，每页带出处档位。

每天 6 小时：上午 3 小时约 2.5 小时净讲授，下午 1.5 小时讲授 ＋ 1.5 小时上机。

**实际页数**：138 / 120 / 104 / 117 / 100，**全套 579 页**。按 4 小时讲授算，
节奏是每页 2 分钟左右——所以单页信息量要压住：一条主张、一个例子、一句判据，不堆满。

**模块编号跨天连续**：第 1 天 M1–M5，第 2 天 M6–M14，第 3 天 M15–M19，
第 4 天 M20–M26，第 5 天 M27–M33。学员在讲义里按编号能找回任意一节。

### 为什么不按书的章节顺序讲

高管只参加第 1 天全天和第 2 天上午，而上册的高管议题（第 10 章采用率、
第 11 章计价与责任、第 13 章合规备案）全部落在书的后半。照书序讲，高管离场时
刚听完第 3 关切片，最需要他们在场的三章一场没赶上。

**所以课程按听众重排，不按书序。** 这是整个课程设计最主要的一处结构判断。

### 下册第 6 章为什么拆开

第 5 天的立意不是“学 DeepSeek Harness”，是**拿四层骨架当尺子去量两个真实开源
项目**。据此：§6.1–6.2（七要素对应哪几层、硬规矩落到工程上）属于下册主线，
留在第 3 天；§6.3–6.5（Semantica 参照实现、覆盖 5/7、什么时候不该用）与别册二
同性质，挪到第 5 天，两者并列成两个样本。

### 裁剪清单

按 100 页／天的密度，教材里需要裁掉的内容很少。原则是：**理论主干全部进课堂，
长清单和完整模板进讲义**。比如变更单 20 个字段，课上只讲最容易被删掉的两栏，
完整字段表放讲义；五句拒绝话术，课上练最值钱的一句，五句全文放讲义。

每天讲义末尾的“课后自读”给出裁掉内容的章节号——不是丢掉，是挪位置。

## 金句页：出处是硬要求

`deck_kit.maxim()` 画的是整页一句话的金句页，五天课件各插了 3 页（模块分隔页之后），
宣讲版《FDE 十二条》整本都由它构成。

**这个原语强制要出处**，档位三档，和书里的证据分档同一套规矩：

| 标记 | 含义 | 台上怎么说 |
|---|---|---|
| **逐字** | 两册正文里的原句 | 可以说“书里原话是” |
| **提炼** | 书里有完整论证，这句是为讲台压缩的 | 说“这本书的意思是”，别说“原话是” |
| **合成** | 要两处论证合起来才成立 | 两处出处都要给 |

理由：**一句话越好记，越容易被转述成“书里说的”。** 标了出处听众能回去查，
查得到这句话才立得住。查不到的金句是负债——它会连累同一页上那些查得到的。

新增金句前先 `grep` 一遍两册，确认它到底是哪一档，别默认写“逐字”。

## 课件和教材的差别

只有一条：**每讲一条理论，配一个例子。**

例子只能取自以下四类，**不新编、不引用竞品文字**：

1. 各章开头的现场速写（“凌晨两点的那通电话”“同一笔款，扣了两次”）
2. 书里已有的六个完整案例（下册四个案例章 ＋ 上册两个决策复盘）
3. Lab 实测数字（混合检索 58/59 对纯向量 53/59、40 并发跨轮换零失败）
4. 可查证的外部事实（Palantir 10-K 原文、许可证差异、备案要求）

视觉上例子走 `example()`，琥珀色竖条 ＋ 来源标签。**不写来源的例子不许上台。**

实际覆盖：539 页里 416 页挂着带来源的例子卡（77%）。其余是封面、模块分隔页、
本节目标页、开篇场景页（场景本身就是例子）、清单页、插图页和收尾页。
插图页不挂例子卡：图的来源写在页脚，而图本身通常就是那个例子的画面。

## 书里的插图，哪几张进了课件

教材有 62 张 TikZ 插图（见 `build/README.md`）。课件用了其中 **14 张**，
（新增的两张是两册的题词页，课件不收——课件有自己的金句页 `maxim()`。）
不是挑剩下的，是按两道关卡筛下来的。

**第一道：字号。** 图里的标签是 8pt，贴进 13.33 英寸宽的幻灯片之后，
等效字号 ＝ 8 × 缩放倍数。课件最小的字是 10.5pt（例子卡的来源标签），
低于它投影仪后排看不见。`figures.fit_pt(宏名, 宽, 高)` 就是算这个的，
**贴之前先算一遍**。

算下来的形状是：整页放（12.3 × 5.2 英寸）时，宽高比 1.4 以上的图才够 10.5pt；
页内放时更苛刻——图总是被高度卡住，所以 `等效字号 ≈ 1.36 × 可用高度 × 宽高比`，
一页里挤出 3.6 英寸高的话，要宽高比 2.15 以上。**竖长的图只能整页放，
再竖的（宽高比 1.1 以下，比如遗留系统四种方式、国企银行采购）根本进不来**，
要用就得按 16:9 重画，那是另一件事。

**第二道：这张图比课件那页现在的样子多讲出什么。** 够格的三种：

| 够格 | 例子 |
|---|---|
| 那页现在是表或清单，而图讲的是**形状** | 技术债四象限——表把四格拍平成四行，两条轴就没了，而「说不清为什么欠的债已经滑到鲁莽区」这句判据靠的正是横轴 |
| 那页讲了结论，图给出**结论的机制** | 三层评估集——表说清了谁负责，说不清三层各自怎么长大，而那才是不能互相替代的原因 |
| **比喻**——课件根本没有画面 | 七张比喻图全部进来了。在这之前课件五百多页一张图都没有 |

不够格的，一张都别贴：

- **课件已经用 `steps()` / `contrast()` / 卡片阵列做出了图的效果。** 四层骨架、
  四段式翻译、Prompt 四层、离线包五步都属于这类——课件那页的字比图大，换成图是降级。
- **图只是把同样的文字换个排布。** 回滚那张的主张（先问撤不回来什么，再定灰度）
  课件的例子卡已经写在那儿了。
- **课件本来就没讲这一节。** 显存预留那张、信创三条路径那张都很好，但课件按裁剪清单
  没收这些内容——**配图不是往课程里加内容的后门**。

筛下来 14 张：上册 6（六关四条回流、失速三处、比喻 4/5/6/7）、
第 2 天 5（三层评估集、技术债四象限、竖着切、比喻 1/2）、
第 3 天 1（比喻 3）、第 4 天 2（四种编排拓扑、三类漂移）。第 5 天一张没进——
那一天讲的是拿骨架去量两个开源项目，教材里没有对应的图。

其中「失速集中在三个位置」是**替换**不是新增：图 25 把原来那页的三个等宽方框、
那句「混着用只会卡得更久」和整张例子卡全包了，还多给出三处在关卡轨上的位置，
留着原页就是同一件事讲两遍。

**怎么贴**：`figpage(s, 宏名, 标题, 来源, note=...)` 整页一张图；
比喻图用 `figplate(s, 宏名, 来源)`——比喻图自带标题和正文，再加页面标题就是
同一句话说两遍，还白占掉半英寸。图的底边必须停在页脚上方，否则版式核算会把页脚
当成「图这个框里的文字」，报一处撑破框。

**验证**：本机不能开 pptx。除了 `check_layout.py` 按坐标核算，还可以把 PNG 缩到
投影仪上的实际像素（`1920 × 图宽英寸 ÷ 13.333`）再看一眼——这是唯一能真正判断
「后排看不看得清」的办法。

讲师改内容直接改 `dayN.py` 里的字面量，改完重跑构建即可。要调整视觉（配色、
字号、构件），改 `deck_kit.py`，五天一起生效。

## 示例产物图（`artifacts.py` → `assets-slides/`）

M4 的需求发现方法和 M6 的三层评估集，原来在课件上全是**字段名和原则的表格**：
「观察记录表有六类字段」「服务蓝图有四条泳道」「评估集分三层」。学员记得住条目，
但没见过一份填完的东西长什么样，回去还是不会用。`artifacts.py` 补的就是那一层——
七张拟真产物图，每一张都是**填完的**：带具体数字、具体对话、具体的错。

| 图 | 对应 | 这张图要证的事 |
|---|---|---|
| `interview` | §4.2 情境访谈 | 三次「我复述 → 对方纠正」，把进场前的假设整个推翻 |
| `shadow` | §4.3 影子跟随 | 异常率与「绕开系统 33%」——能直接写成验收指标的那个数 |
| `blueprint` | §4.4 服务蓝图 | 两个失败点都落在可见性线以下，员工只看得到总时长 |
| `ontology` | §4.4 本体三要素 | 蓝图看不到的前置条件，写出来才发现数据不存在 |
| `mining` | §4.5 流程挖掘 | 客户说 5 步，日志里 217 种变体，最常见的只占 41% |
| `ladder` | §4.6 提问工具箱 | 五个为什么撞上「张会计没提过」时那一下退回 |
| `evalsets` | §8.2 三层评估集 | 一句没法执行的需求，和它可执行的那个版本 |
| `skill` | 下册 §10.2、§10.5 | 一份技能、它的命中集、它的护栏用例，三样同框 |
| `harness` | 别册二全册 | DeepSeek Harness 按四层骨架重排的功能架构 |
| `semantica` | 下册 §6.4 | 七要素量一遍：覆盖 5/7，缺口归谁补 |

三条纪律：

1. **前八张讲同一个流程**——一张报销单从提交到打款。同一个场景用七种方法看，
   差别才看得出来；换七个场景就变成七个孤立的示范了。回归集里 `R-022`
   那条「审批人已休假，助手仍返回该人姓名」，正是第一张访谈图里挖出来的痛点。
   **最后两张是例外**：它们讲的是两个真实开源项目，所以戳换成溯源文案，
   不能盖「非真实客户数据」——那会把一份有出处的判断标成虚构。
   这两张刻意不画组件图：照 README 画组件图，学到的是这个项目怎么搭的；
   按尺子重排，学到的是下次遇到另一个项目该怎么问。
2. **戳盖在图里，不在页脚。** 「教学示例 · 非真实客户数据」跟着图走——
   这些图会被截去转发，落款丢了戳还在。
3. **宽高比压在 2.4–2.55。** 再高，贴到幻灯片上就要按高度缩，字号掉下去，
   后排看不清。塞不下就砍内容，不要拉高画布。
