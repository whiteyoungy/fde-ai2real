## 1. 目标与验收标准

### 1.1 目标
产出一本中文教材，读者学完后具备独立承担 AI FDE 岗位的能力：能走完客户现场的完整交付闭环，能独立设计与实现企业级 AI 系统，并了解中国市场的特定落地约束。

### 1.2 读者画像（已确认）
- 技术侧：AI 与工程两边均有基础。Python/SQL/API/Docker 熟练，对模型、Prompt、微调有概念。
- 缺口：**落地打法**——需求发现、边界谈判、评估护栏、客户政治、生产推广、采用率运营。
- 因此：技术基线章节压缩，方法论与案例章节加重。

### 1.3 验收标准
| 项 | 标准 |
|---|---|
| 篇幅 | 排版后 250–280 页 A4，正文 20–24 万中文字符。**200 页是下限不是上限**——内容质量优先于篇幅控制，宁可多写不可注水 |
| 配比 | 讲解 ≈60%，动手 Lab ≈25%，案例复盘 ≈15% |
| 事实基础 | 参考文献 ≥120 条一手来源；薪酬、市场、法规、框架 API 四类数据必须联网核实并标注检索日期 |
| Lab | 12 个 Lab 全部有可运行代码与验收脚本；无 GPU 环境有降级路径 |
| 交付物 | 分章 Markdown（每章独立文件）+ 合并生成的可打印 PDF（含目录、页码、代码高亮） |
| 中国内容 | 第五部 40 页，覆盖交付文化、国产栈、信创、法规备案 |

### 1.4 明确不做（YAGNI）
- 不写基座模型预训练、不写算法论文推导
- 不做视频、不做课件 PPT
- 不做交互式在线练习平台
- 不覆盖 Palantir Foundry 等闭源平台的产品操作手册

## 2. 组织原则

**方法论主导，技术栈作纵深参考，案例焊死两者，中国专章做本地化。**

不按源报告的"五层技术栈"线性组织——读者在已掌握区域会空转。改为：
1. 先建立角色心智模型（我是谁，我的边界在哪）
2. 再给作业闭环 SOP（我每天怎么干）
3. 技术深水区按"可能不会的部分"展开，作为随查手册
4. 案例复盘把方法论与技术焊接成肌肉记忆
5. 中国专章处理国内特有约束
6. 职业化收尾

## 7. 写作规范

| 项 | 规范 |
|---|---|
| 语言 | 简体中文；技术术语首次出现给英文原文 |

| 单章写不够深 | 每章目标页数是下限，未达标说明调研不足，回补资料而非硬凑 |
| 各章风格漂移 | 先写第 1、7、17 章作为风格样板，定稿后再批量推进 |
| 案例编造失真 | 严格区分真实案例与合成案例并显式标注；合成案例基于可查证的行业常态 |
| 法规内容过时或不准 | 联网核实，标注检索日期，并加免责声明「以最新官方发布为准」 |
| Lab 代码跑不起来 | 每个 Lab 必须实际执行验收脚本；提供 Docker Compose 一键环境与无 GPU 降级路径 |
| 国产栈无法实测（缺昇腾硬件） | 明确标注哪些步骤为实测、哪些为基于官方文档的流程说明 |
