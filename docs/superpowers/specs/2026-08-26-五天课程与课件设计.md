# 五天 FDE 课程与课件设计

日期：2026-08-26　　分支：`book/fde-handbook`

## 1. 目标

把《AI 前线部署工程师实战教程》（上下册 + 两本别册 + 12 个 Lab）改编成一门五天
的企业内训课，产出可直接开讲的 `.pptx` 课件与学员讲义。

课件不是教材的缩写版。它相对教材的增量只有一条：**每讲一条理论，配一个例子**。

## 2. 硬约束

| 约束 | 来源 |
|---|---|
| 第 1、2 天讲上册，第 3、4 天讲下册，第 5 天讲别册二与 Semantica | 用户指定 |
| 高管只参加第 1 天全天 + 第 2 天上午 | 用户选定 |
| 每天 6 小时，4 小时讲授 + 2 小时上机 | 用户选定 |
| 产出真 `.pptx`，沿用 `build/build_deck.py` 的视觉 | 用户选定 |
| 不新编竞品案例、不引用竞品文字 | 全书红线 |
| 代码非必要不重写，跑过的不重跑 | 用户既有约束 |

最后一条落到本设计上：五次上机全部使用 `labs/` 中已实现、`verify.sh` 已通过的
现成 Lab，不写新 Lab；`build/build_deck.py` 一行不动，另起 `slides/deck_kit.py`。

## 3. 课程主线

### 3.1 为什么不按书序讲

上册的高管议题（第 10 章采用率、第 11 章计价与责任、第 13 章合规备案）全部落在
书的后半。照书序讲，高管离场时刚听完第 3 关切片，最需要他们在场的三章一场没赶上。

因此课程按**听众**重排，不按书序。这是本设计最主要的一处结构判断。

### 3.2 五天骨架

| 天 | 时段 | 听众 | 主题 | 覆盖章节 |
|---|---|---|---|---|
| D1 | 全天 | 高管＋FDE | 风险转移、六道关卡、怎么死、选题、定界 | 上册 1–5 |
| D2 | 上午 | 高管＋FDE | 验收指标、采用率、合规备案、计价与责任 | 上册 8、10、13、11、附录 A |
| D2 | 下午 | FDE | 切片、最小可执行业务模型、上线、驻场、资产化、决策复盘 | 上册 6、7、9、12、14、15、16 |
| D3 | 全天 | FDE | 工程基线、规约驱动、企业集成、数据管道、本体落到哪几层 | 下册 1–5、§6.1–6.2 |
| D4 | 全天 | FDE | Agent 编排、护栏与可观测性、评估、国产化、四案例串讲 | 下册 7–11、12–15、16、17 |
| D5 | 全天 | FDE | 读一个开源项目，判断它能不能进你的交付 | 别册二全册、下册 §6.3–6.5 |

D2 上午以「附录 A 立项前 12 问」当场对着学员自己在跑的项目过一遍收尾——高管带走
的是一份填完的表，不是一份笔记。

### 3.3 下册第 6 章为什么要拆开

第 5 天的立意不是「学 DeepSeek Harness」，是**拿四层骨架当尺子去量两个真实开源
项目**。据此：

- §6.1–6.2（七要素对应哪几层、三条硬规矩落到工程上）属于下册主线，留在 D3；
- §6.3–6.5（Semantica 参照实现、覆盖 5/7、什么时候不该用）与 dsh 别册同性质，
  挪到 D5，两者并列成两个样本。

## 4. 单日时间盘

上午 3 小时约 2.5 小时净讲授；下午 1.5 小时讲授 + 1.5 小时上机。

| 天 | 上机 | 配套章 | 选它的理由 |
|---|---|---|---|
| D1 | Lab-11 工作流发现（纯文档） | 上册 4、5 | 高管与工程师混编分组，全课唯一一次 |
| D2 | 决策复盘研讨（非上机） | 上册 15、16 | 分组读被否决的方案，辩你会否决哪个 |
| D3 | Lab-04 混合检索 + 质量诊断 | 下册 5 | 有实测数字，CPU 可跑 |
| D4 | Lab-05 Evals + CI 门禁 | 下册 9 | 注入劣化必红、恢复必绿，课堂有明确红绿时刻 |
| D5 | 开源组件进场评估 | 别册二、下册 §6.3 | A 路径有网实跑 dsh，B 路径断网做文档评估 |

每天 45–55 页，全套约 250 页。

## 5. 例子规则

课件里每条理论主张必须配一个例子，例子只能取自以下四类，不得新编：

1. 各章开头的现场速写（如「凌晨两点的那通电话」「同一笔款，扣了两次」）
2. 书里已有的六个完整案例（下册四个案例章 + 上册两个决策复盘）
3. Lab 实测数字（如混合检索 58/59 对纯向量 53/59、40 并发跨轮换零失败）
4. 可查证的外部事实（Palantir 10-K 原文、许可证差异、备案要求）

视觉上例子走 `card()`，与理论正文行区分。

## 6. 裁剪清单

裁掉的内容进当天讲义的「课后自读」，给出章节号，不是丢弃。

**上册**：§1.2 四家公司（压成一张对照表）、§4.5 流程挖掘与 §4.6 提问工具箱（并进
Lab-11 任务书）、§5.6 变更管理（一张表）、§11.4 集成商生态、§11.5 预算周期、
§13.5 行业额外监管（一张表）、§14.4 职业倦怠。

**下册**：§2.5 会不会变成瀑布、§2.8 基准规格、§3.6 Git 协作规范、§4.6 国内 IM
平台（一页）、§5.2 Airflow（一页）、§7.2 长上下文与 §7.6 LangGraph 代码细节
（压缩）、§8.3 推理性能三档（压成决策表）、§10.5 Lab-09 任务书、§17.1 题库。

## 7. 产出物

```
slides/
  deck_kit.py         版式原语，自 build/build_deck.py 复制扩展，原文件不动
  day1.py … day5.py   每天一份，内容即 Python 字面量
  build_slides.py     入口：python3 slides/build_slides.py [day1..day5|all]
  README.md           课程大纲、时间表、讲师须知、上机环境准备
  handouts/day1.md …  学员讲义：上机任务书 + 课后自读清单 + 空白模板
  *.pptx              产物，按现有 .gitignore 的 `*.pptx` 规则不入库
```

## 8. 实施顺序

先只做 D1 完整课件交付确认版式与信息密度，认可后再一次性铺 D2–D5。250 页一口气
做完再返工代价过大。

## 9. 验收

- 五份 pptx 均能生成，16:9，中文字体走 eastAsia 不回退；
- 每天页数落在 45–55 之间；
- 抽查任意十页讲理论的页，均有例子，且例子可回溯到第 5 节四类来源之一；
- 讲义中「课后自读」条目与第 6 节裁剪清单逐条对应；
- 上机全部指向 `labs/` 中已通过 `verify.sh` 的 Lab，无新增 Lab。
